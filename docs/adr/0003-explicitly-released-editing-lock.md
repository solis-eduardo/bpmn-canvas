# Lock released explicitly or by expiry

The legacy stack was explicit about having no concurrent editing lock at all: "if two people save the same file, the last one wins." That was acceptable with a single shared username/password, but with individual accounts (ADR-0001) and per-Diagram Collaborators, silent collisions become a real risk of lost work.

A Lock is held per Diagram: opening another Editor does not replace or release a User's existing Locks. Leaving or closing the Editor does not release the Lock by itself. The holder can release each Lock explicitly, and an Administrator can force-release it. The holder's open Editor sends a Heartbeat every 30 seconds while the holder is actively using it; a Lock that goes **5 minutes without a Heartbeat expires** and is released by the scheduled `locks:expire` command (TTL configurable through `LOCK_TTL_MINUTES`). Other eligible Users can request a held Lock, which notifies the holder but never transfers the Lock automatically, including after 30 seconds. A Fork (independent copy of the Diagram) remains an immediate alternative for someone who cannot wait.

The Heartbeat carries the Editor's unsaved content when there is any, kept on the Diagram as a draft. When a Lock expires, the draft (if any) is saved as a **provisional Version** attributed to the former holder, named "Provisional version (Lock expired)", before the Lock is released. A normal save discards the draft, since the content is then a regular Version. This way an expiry never loses the holder's last synced work.

We first chose explicit release only, because browser/tab lifecycle alone is not a reliable sign that editing has ended, and that left an abandoned Lock able to block editing indefinitely. Expiry is safe now because it is not driven by the tab lifecycle: the Heartbeat stops only after the Editor was closed or untouched for about 3 minutes, and the unsaved content is preserved as a Version instead of being discarded. Expiry only ever **releases**: it never transfers the Lock to a requester (ADR-0011 still requires a human picking the recipient). The trade-off is that a holder who is idle for more than the TTL loses the Lock and has to acquire it again, possibly finding it taken, in which case their last content is in the Version history.

Whoever opens a locked Diagram gets the read-only Viewer instead of the Editor: a red notice names the holder, saving is impossible, and the only actions are requesting the Lock (or, for an Administrator, force-releasing it). Users without edit permission are a separate case: they never reach the Diagram at all (an Administrator sees it in the Viewer, per ADR-0006).
