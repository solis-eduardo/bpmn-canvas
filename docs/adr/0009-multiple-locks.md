# A User may hold multiple Locks

A Lock belongs to one Diagram, so a User may hold Locks on multiple Diagrams at once. Navigation and closing the Editor never release a Lock by themselves: a Lock is released explicitly by its holder or an Administrator, or by expiry after 5 minutes without a Heartbeat (ADR-0003), which saves any unsaved content as a provisional Version. Each Lock expires independently, so a User keeping one Editor active does not keep their other Locks alive. A different editor may request a held Lock and notify its holder, but the request never triggers an automatic transfer, regardless of elapsed time. This avoids silently releasing a Diagram when its editor changes screens and keeps the transfer decision with an authorized actor.

## Amendment: a Lock is also released when its holder loses edit rights

The list of ways a Lock ends is no longer only "explicit release, or expiry". It is also released as soon as its holder can no longer edit the Diagram (see the amendment to ADR-0003), with the holder's draft discarded rather than kept as a provisional Version. Because one User can hold Locks on several Diagrams, an access change can affect many Locks at once: removing a Member from a Workspace, or a Keycloak group sync, reconciles every Lock that User holds in that Workspace (`LockService::reconcileHeldBy`), while each Lock is still judged independently by whether its holder can edit that Diagram.
